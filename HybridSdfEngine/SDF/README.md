# Сцена, трассировка и освещение

- `HybridSdfEngine.SDF.Scene` хранит фиксированный состав объектов и источников света.
- `HybridSdfEngine.SDF.Tracing.SceneTracer` выполняет `Trace`, `Occluded`, `Map` и `GetClosestObject`.
- `HybridSdfEngine.Render.BsdfRenderer` рассчитывает освещение, тени и BSDF-пути через `RenderRay`.
- `DiffuseRenderer` сохранён как совместимое имя этого рендерера.

`Scene` — обычный конкретный класс. Он копирует входные коллекции и предоставляет
их через доступные только для чтения `Objects` и `Lights`. Сами объекты и источники
остаются изменяемыми. Один `SceneTracer` можно передать в `DiffuseRenderer`, чтобы
запросы геометрии и освещение использовали одну сцену.

```csharp
using System.Numerics;
using HybridSdfEngine.SDF;
using HybridSdfEngine.SDF.Light;
using HybridSdfEngine.SDF.Objects;
using HybridSdfEngine.SDF.Tracing;
using HybridSdfEngine.Render;

var scene = new Scene([
    new SdfSphere(new(0, 1, 3), 1),
    new SdfPlane(Vector3.Zero, Vector3.UnitY)
], [new SunLight(new(0, -1, 0.5f), Vector3.One, 1f)]);
var tracer = new SceneTracer(scene);
var renderer = new DiffuseRenderer(tracer);
Vector3 pixel = renderer.RenderRay(new(0, 1, -10), Vector3.UnitZ);
```

`SdCompositor` в `SDF.Utility` оставлен как тонкая оболочка совместимости:
он передаёт вызовы в `Tracer` и `Renderer`. Новый код приложения, проверки и
бенчмарки используют отдельные классы. `MarchResult` находится в `SDF.Tracing`.

## Гибридная трассировка

Доступны также `SdfCylinder`, `SdfTorus`, `SdfCone` и `SdfTriangle`.
Параметры, ориентация и примеры — в [описании примитивов](Objects/README.md).

`SceneTracer.Trace` ищет ближайшую поверхность двумя способами:

1. У объектов с `IRayIntersectable` вызывает `TryIntersect` и запоминает ближайшее прямое пересечение.
2. Объекты, реализующие только `ISdfObject`, обходит ray marching до расстояния этого пересечения (или `maxDistance`, если его нет).
3. Возвращает более близкое SDF-попадание либо найденный аналитически объект.

Сферы, плоскости, коробки, цилиндры, конусы и треугольники реализуют оба способа.
Они сохраняют `DistanceTo`; у треугольника расстояние неотрицательное, поскольку
у него нет внутреннего объёма. Торус обрабатывается через SDF ray marching.
В текущей демонстрационной сцене все объекты пересекаются напрямую;
пошаговый цикл не запускается.

```csharp
var geometry = new Scene([
    new SdfSphere(new(0, 1, 3), 1),
    new SdfBox(new(2, 1, 3), new(1)),
    new SdfPlane(Vector3.Zero, Vector3.UnitY)
]);
var geometryTracer = new SceneTracer(geometry);

MarchResult hit = geometryTracer.Trace(
    origin: new(0, 1, -10),
    direction: Vector3.UnitZ,
    maxDistance: 1000f,
    maxSteps: 1000);

if (hit.Hit)
{
    var normal = hit.ClosestObject!.GetNormal(hit.CollisionPoint);
    var context = hit.ClosestObject.GetTextureContext(hit.CollisionPoint);
    var albedo = hit.ClosestObject.Material?.Sample(context).Albedo ?? Vector3.One;
}
```

`Trace` нормализует направление. `Dist` и `maxDistance` задаются в мировых единицах. `maxSteps` ограничивает только SDF-цикл. Старый `SdCompositor.RayMarch(origin, direction)` сохранён как совместимый вызов `Tracer.Trace`.

## Добавление объектов

- Для процедурной формы достаточно `ISdfObject`. `DistanceTo` должен возвращать корректное signed distance либо консервативную оценку расстояния до поверхности: нельзя переоценивать безопасный шаг. Нормаль можно реализовать аналитически или использовать реализацию интерфейса по конечным разностям.
- Если есть формула прямого пересечения, объект дополнительно реализует `IRayIntersectable`. `TryIntersect` получает единичное направление и возвращает ближайший неотрицательный параметр луча в пределах `maxDistance`. Прямой вызов этого метода предполагает конечные корректные входы и геометрию (положительный радиус/полуразмеры).
- Деформацию, smooth union или CSG-композицию следует оформлять отдельным `ISdfObject`, вычисляющим итоговое поле. Наличие аналитических примитивов внутри такого объекта само по себе не делает итоговую поверхность аналитической.

Состав объектов и источников света копируется при создании `Scene`. Изменение положений, вращений и цветов существующих экземпляров видно в следующих кадрах; для изменения состава нужно создать новые `Scene`, `SceneTracer` и `DiffuseRenderer`. Обновляйте объекты перед запуском параллельного рендера.

## Поведение на границах

- Пересечения позади начала луча исключаются. Луч изнутри тела ищет поверхность выхода; SDF-путь использует абсолютную величину signed distance для шага.
- Отдельные объекты сцены трактуются как отдельные поверхности. Это не автоматическое CSG-объединение их внутренних объёмов. Для такого объединения нужен составной SDF-объект.
- Плоскость — двусторонняя поверхность при трассировке; её `DistanceTo` остаётся знаковым для использования в CSG.
- Начало точно на поверхности считается попаданием с расстоянием 0. `DiffuseRenderer` смещает начало теневого луча; при собственных запросах от поверхности смещение задаёт вызывающий код.
- Коробка хранит полуразмеры. Луч переводится обратным вращением в её локальные координаты. На рёбрах нормаль одной из граней выбирается детерминированно.
- Если SDF-цикл исчерпал бюджет, `Hit == false` и `StepLimitReached == true`. Аналитический объект позади незавершённой трассировки не выдаётся за подтверждённое попадание.
- SDF-попадания имеют допуск 0.001; аналитические ограничены точностью арифметики. Поэтому новый кадр может немного отличаться на силуэтах и заполнить пропуски старого marcher возле горизонта.

## Материалы и текстуры

Доступны `DiffuseMaterial`, `PbrMaterial` (GGX, roughness/metallic) и
`DielectricMaterial` (Френель, отражение и преломление). Контракт и настройки
вторичных лучей описаны в [BSDF](../Materials/Scattering/README.md).

Примитивам можно назначить `Material`. `DiffuseMaterial` получает альбедо,
излучение и карту нормалей через `ITexture<Vector3>`. Доступны постоянные,
шахматные, RGB/RGBA-изображения и трипланарные цветовые текстуры; `ChannelTexture`
извлекает скалярную карту. UV и касательный базис предоставляются объектом.
При `Material = null` используется белое диффузное покрытие. Цвет задаётся
через альбедо `DiffuseMaterial`; отдельного `Color` у геометрии нет.

Примеры и ограничения описаны в [материалах](../Materials/README.md).
Основная демонстрационная сцена использует шахматный материал пола.

## Источники света

Все источники предоставляют изменяемые `Color` (линейный RGB) и `Intensity`.
Используйте конечные неотрицательные значения. Меняйте параметры между кадрами,
до запуска параллельного рендера.

```csharp
var spot = new SpotLight(
    position: new(0, 5, -2),
    rayDirection: new(0, -1, 0.4f),
    color: new(1, 0.85f, 0.7f),
    intensity: 20f,
    innerAngle: MathF.PI / 12f,
    outerAngle: MathF.PI / 6f);

var panel = new AreaLight(
    position: new(0, 5, 0),
    rotation: Quaternion.CreateFromAxisAngle(Vector3.UnitX, MathF.PI / 2f),
    size: new(3, 2),
    color: Vector3.One,
    intensity: 3f,
    samplesPerAxis: 2);

var litScene = new Scene([
    new SdfSphere(new(0, 1, 0), 1),
    new SdfPlane(Vector3.Zero, Vector3.UnitY)
], [spot, panel]);
var litRenderer = new DiffuseRenderer(litScene);
```

`SpotLight` затухает как `1 / distance²`. `RayDirection` направлен **от источника**
и нормализуется при присваивании. `InnerAngle` и `OuterAngle` — половинные углы
конуса в радианах, отсчитываемые от его оси:
`0 <= InnerAngle <= OuterAngle < π/2`, причём `OuterAngle > 0`.
Между границами применяется плавный переход `smoothstep` в пространстве косинусов.
Для одновременного изменения обоих углов есть `SetConeAngles(inner, outer)`;
равные углы дают резкую границу.

`AreaLight` — прямоугольная панель. `Size` задаёт полную ширину и высоту;
`Position` — центр; нормализованный `Rotation` поворачивает локальные оси панели.
Без поворота лицевая нормаль направлена вдоль `+Z`. В примере поворот вокруг X
на `π/2` направляет панель вниз. `Normal` возвращает текущую мировую нормаль.
По умолчанию панель излучает только с лицевой стороны; `TwoSided = true` включает обе.
`Intensity` задаёт множитель излучения поверхности: при той же интенсивности
увеличение площади увеличивает суммарное излучение.

`SamplesPerAxis` задаёт сетку от 1×1 до 32×32. Значение 1 использует центр,
значение 2 (по умолчанию) — центры четырёх ячеек. Выборки детерминированы,
поэтому свет не мерцает от кадра к кадру. Каждый вклад учитывает площадь,
косинус со стороны излучателя и обратный квадрат расстояния. `DiffuseRenderer`
добавляет косинус со стороны освещаемой поверхности и усредняет вклады.
При SSAA расчёт повторяется для каждой субпиксельной выборки.

Для собственного шейдера используйте весь контракт `ILight`:

```csharp
Vector3 lighting = Vector3.Zero;
int count = light.SampleCount;
for (int i = 0; i < count; i++)
{
    LightSample sample = light.Sample(point, i);
    lighting += sample.Radiance * MathF.Max(Vector3.Dot(normal, sample.DirectionToLight), 0);
}
lighting /= count;
```

`Sample(point)` возвращает только первую выборку. У `SunLight`, `PointLight`
и `SpotLight` выборка одна, а интерфейс предоставляет совместимую реализацию
индексированного вызова. Обычный `Sample` не выделяет память в куче.

Панель пока не добавляет видимую геометрию в сцену. Вблизи панели сетку нужно
повышать для точности; детерминированная квадратура с малым числом выборок
остаётся приближением.

Модели конуса и излучающей поверхности описаны в
[PBRT: Point Lights](https://pbr-book.org/4ed/Light_Sources/Point_Lights) и
[PBRT: Area Lights](https://pbr-book.org/4ed/Light_Sources/Area_Lights).

## Тени

`DiffuseRenderer.RenderRay` по умолчанию проверяет видимость каждой ненулевой выборки света,
обращённой к поверхности. `PointLight` и `SpotLight` дают жёсткие тени;
`AreaLight` проверяет отдельные точки панели и усредняет все выборки, включая
перекрытые. Это даёт полутень; на редкой сетке её переходы могут быть ступенчатыми.
Текущий `SunLight` имеет единственное направление и даёт жёсткие тени.
Все объекты считаются непрозрачными, непрямое освещение пока не рассчитывается.

```csharp
litRenderer.ShadowsEnabled = true;       // По умолчанию true.
litRenderer.ShadowBias = 0.002f;         // Смещение начала и отступ от конца луча.
litRenderer.ShadowMaxDistance = 1000f;   // Только для источников на бесконечности.
litRenderer.ShadowMaxSteps = 256;        // Бюджет SDF-шагов одного теневого луча.
```

Параметры меняются между кадрами. Для конечного источника направление
пересчитывается от смещённого начала до той же точки света, а конец луча
укорачивается на `ShadowBias`. Поэтому препятствия за лампой не затеняют её.
`ShadowMaxDistance` ограничивает тени от `SunLight`; для конечных источников
используется фактическое расстояние, даже если оно больше этой настройки.

`ShadowBias` задаётся в мировых единицах. Значение по умолчанию немного превышает
SDF-допуск `0.001`: слишком маленькое смещение вызывает самозатенение,
слишком большое — потерю контактных теней и пропуск близких препятствий.
Его нужно подбирать под масштаб и точность координат сцены.

Публичный `SceneTracer.Occluded(origin, direction, maxDistance, maxSteps)` ищет любое
пересечение поверхности до конца отрезка. Направление нормализуется,
`maxDistance` должен быть конечным и неотрицательным. Для нулевой длины
возвращается `false`, пересечение точно на конце отрезка исключается.
При прямом вызове смещение начала и отступ от источника задаёт вызывающий код.
Аналитические объекты проверяются до первого препятствия; для остальных
используется SDF-трассировка. Если её бюджет закончился до доказательства
свободного пути, результат `true`: это может дать лишнюю тень, но не утечку света.
Для SDF границы пересечений определяются с допуском `0.001`.

Теневые лучи не выделяют память в куче. Число дополнительных запросов видимости
растёт с количеством источников, выборок панели и субпикселей SSAA.
`ShadowsEnabled = false` оставляет расчёт освещения без проверок видимости.

## Проверка

```powershell
dotnet run --project Tests/HybridSdfEngine.Tests/ConsoleDisplayChecks.csproj -c Release
```

Запускаются проверки трассировки, света, теней и консольного вывода. Покрыты прямые/касательные/параллельные лучи, начало внутри и на поверхности, ограничение дальности, смешанные сцены, исчерпание шагов, нормали на рёбрах и 500 случайных вращений/переносов. Для света проверяются конус, затухание, поворот и стороны панели, некорректные параметры и сходимость интегрирования по площади. Для теней проверяются аналитические и SDF-препятствия, дальность, отсутствие самозатенения плоскости, независимость источников, полутень панели и остановка поиска на первом препятствии.

## Запуск приложения

В интерактивном режиме доступны WASD и поворот камеры при зажатой ПКМ.
Нажмите F1 для включения управления, Esc для отключения.
Подробности о глобальном вводе и API — в [Input](../Input/README.md).
Контроллер и назначения клавиш находятся в [приложении](../../AstralGates/Input/README.md).

Для сохранения анимации в GIF используйте `--gif`:

```powershell
dotnet run --project AstralGates/AstralGates.csproj -c Release -- --gif artifacts/render.gif 320 180 25 4
```

Настройки и API описаны в [экспорте GIF](../Export/README.md). Требуется FFmpeg в `PATH`.

В обычном терминале запускается анимированный консольный рендер. Ctrl+C завершает
цикл и освобождает `ConsoleDisplay`, восстанавливая курсор и режим терминала:

```powershell
dotnet run --project AstralGates/AstralGates.csproj -c Release
```

Для проверки без интерактивной консоли есть отдельный режим локального тестового проекта. Он запускает
настоящий `RenderPipeline`, обновляет сцену, рисует два кадра с тенями и SSAA4,
проверяет конечность цветов и наличие освещённых пикселей, выводит кадры в
`ConsoleDisplay` с потоком памяти и завершается:

```powershell
dotnet run --project Tests/AstralGates.Tests/AstralGates.Tests.csproj -c Release -- --smoke-test
```

Прежние замеры отдельных режимов рендера доступны через `--timings` в
`Tests/AstralGates.Tests`. Для сравнения производительности используйте
`Tests/AstralGates.Benchmarks`. Все локальные проверки и результаты находятся
в игнорируемой Git папке `Tests/`; основное приложение содержит игровой запуск и экспорт GIF.
