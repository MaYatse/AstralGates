# Быстрый вывод в консоль

Публичные методы сохранены:

```csharp
var display = new ConsoleDisplay(); // Создать один раз, вне цикла кадров.
// В цикле:
display.ColoredGraphic(width, height, pixels);
display.Render();
```

RGB остаётся 24-битным, каждый пиксель занимает две символьные ячейки.
Терминал должен поддерживать ANSI true color, а видимая область — вмещать
`width * 2` столбцов и `height` строк. На Windows включается обработка VT-команд.

Буферы переиспользуются. После прогрева и при постоянном разрешении цветной
рендерер не выделяет память на кадр. RGB-команды формируются напрямую в UTF-8;
соседние пиксели одного цвета используют одну команду. Кадр сравнивается с
последним успешно выведенным кадром. Неизменившиеся участки пропускаются,
неизменившийся кадр не вызывает запись. Все изменения отправляются одной
записью в стандартный поток вывода. Позиционирование строк без перевода строки
предотвращает прокрутку на нижней строке.

После изменения размера окна, `Console.Clear()` или постороннего вывода вызовите
`display.Invalidate()` **перед** следующей подготовкой кадра. Изменение разрешения
и вывод через `MaskGraphics` автоматически вызывают полную перерисовку следующего
цветного кадра. Один экземпляр используется из одного потока; поток, переданный
в конструктор `ConsoleDisplay(Stream)`, остаётся собственностью вызывающего кода.

Проверки и воспроизводимый микробенчмарк без внешних пакетов:

```powershell
dotnet run --project Tests/ConsoleDisplayChecks.csproj -c Release
```

Проверки применяют ANSI-команды к модели экрана и сравнивают цвета после случайных
частичных обновлений. Бенчмарк сравнивает прежнее формирование строк с новым выводом
для кадров 160×90, измеряет время и выделения памяти после прогрева. Используется
`Stream.Null`: результат характеризует подготовку и передачу буфера, а не FPS
реального терминала. Скорость отрисовки терминала и вычисления шейдера измеряются отдельно.
