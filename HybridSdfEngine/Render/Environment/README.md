# Ограниченный PBR для CPU

`RealtimeRenderer` использует те же `Scene`, `SceneTracer`, `IMaterial`, карты
и прямое BSDF-освещение, что `BsdfRenderer`. Вместо случайного вторичного
переноса он использует предрасчёт окружения и ограниченные идеальные лучи.
Реализация использует .NET и не зависит от Windows Terminal или графического API.

```csharp
var realtime = new RealtimeRenderer(scene);
foreach (var receiver in scene.Objects)
    realtime.BakeEnvironmentFor(receiver, new Vector3(0, 5, -3)); // Один раз при подготовке.
Vector3 linearColor = realtime.RenderRay(cameraPosition, direction);
```

Прямой свет сохраняет диффузную составляющую, GGX, Френель, metallic, roughness,
normal map, emission и тени. `RenderRaySample` возвращает guides без повторной
трассировки, с `Filterable=false`: случайного шума вторичного переноса в этом
режиме нет. Это не устраняет aliasing текстур/силуэтов и ошибки ограниченных бюджетов.

## Окружение

`IEnvironmentLight.SampleSpecular` возвращает линейную радианс для направления
и шероховатости. `SampleDiffuse` возвращает irradiance / PI, то есть отклик
единичной ламбертовой поверхности. По умолчанию библиотечный renderer имеет
чёрное окружение; его нужно задать или построить явно.

```csharp
var image = ImageTexture.FromFile("environment.png"); // sRGB декодируется в линейный цвет.
realtime.EnvironmentLight = PrefilteredEnvironmentMap.FromImage(image, resolution: 32, sampleCount: 64);
// Либо постоянное освещение, полезное для настройки и тестов:
realtime.EnvironmentLight = new ConstantEnvironmentLight(new Vector3(0.1f));
```

Картинка должна иметь эквидистантную сферическую развёртку (обычно 2:1).
Ось Y направлена вверх; UV совпадают с развёрткой `SdfSphere`.
`ImageTexture` с линейными float-пикселями допускает HDR-значения; загрузка
через существующий `FromFile` использует декодер RGBA8. Можно также построить
`PrefilteredEnvironmentMap` из функции направления → линейный RGB.

При создании карты источник вызывается один раз на каждый базовый тексель
куба. Затем строятся GGX-уровни шероховатости и cosine-weighted diffuse-карта.
В кадре выполняются билинейные выборки, смешивание уровней и lookup небольшой
общей BRDF-таблицы (split-sum). При нулевой шероховатости используется точный
Schlick-вес идеального отражения. Предрасчёт дорог относительно lookup и не
предназначен для вызова каждый кадр.

`BakeEnvironment` создаёт прямое освещение сцены из одной точки, без вторичных
переходов, и превращает его в дальнее окружение. Точку следует выбирать вне
твёрдых объектов. Это статический снимок: нет параллакса, актуальных отражений
движущихся объектов и автоматического обновления при изменении света.
Повторный bake выполняется явно между кадрами. `BackgroundColor` задаёт фон
основных лучей независимо от освещения окружения.

Общий пробник `BakeEnvironment` содержит все объекты сцены. Если использовать
его на одном из записанных объектов, в отражении может появиться изображение
самого объекта. Для локальных отражений вызывайте `BakeEnvironmentFor(receiver, position)`:
он строит отдельную карту без геометрии и теней получателя в захвате. Реальная
сцена, первичные лучи и вторичные пересечения при этом не изменяются. Другие
объекты остаются в карте. В демонстрации `RenderPipeline.BakeRealtimeEnvironment`
создаёт такие карты для всех объектов сцены.

`SetEnvironmentFor` задаёт готовую карту отдельному объекту, `GetEnvironmentFor`
возвращает его карту или общее `EnvironmentLight`, `ClearEnvironmentFor` убирает
переопределение. Эти изменения, как и запекание, выполняются между кадрами.
Переопределения имеют приоритет над общим окружением; изменение `EnvironmentLight`
не сбрасывает их. При отражённом луче, не встретившем геометрию, используется
окружение поверхности, породившей этот луч.

## Бюджеты и приближения

Стандартные настройки `RealtimeRenderer`:

| Настройка | Значение | Смысл |
|---|---:|---|
| `MaxSecondaryRays` | 2 | Общий лимит вторичных лучей на основной луч |
| `MaxBounces` | 3 | Максимальная глубина; одновременно действует общий лимит |
| `SceneReflectionsEnabled` | true | Идеальные отражения сцены при наличии бюджета |
| `SceneReflectionRoughnessLimit` | 0.05 | Более шероховатые непрозрачные поверхности используют окружение |
| `MaxLights` | 8 | Первые источники в порядке сцены |
| `MaxLightSamples` | 4 | Максимум детерминированных выборок каждого источника |
| `MaxSteps` / `MaxDistance` | 128 / 100 | Геометрические запросы |
| `ShadowMaxSteps` / `ShadowMaxDistance` | 64 / 60 | Теневые запросы |
| `MaxShadowIntersections` | 4 | Максимум проверенных границ прозрачной тени |

Границы входа/выхода стекла учитываются отдельно, включая вложенные IOR и
полное внутреннее отражение. Отражение и преломление складываются с весами
Френеля без случайного выбора ветви. Более весомая ветвь получает бюджет
первой. При двух вторичных лучах обычный проход через замкнутое стекло может
проверить выходную границу и следующий видимый объект. Для сложных вложений
потребуется больший бюджет. Истощённая непроверенная передача возвращает чёрный
цвет, оставшиеся отражения приближаются окружением. Это может давать потемнения
и неточные отражения, но не бесконтрольное разрастание дерева лучей.

Шероховатое преломление приближено идеальным направлением; корректное матовое
стекло и многократное рассеяние требуют BSDF-режима. Окружение приближает
шероховатые отражения, а динамический луч под порогом шероховатости считается
идеальным. Не выполняется стохастическое diffuse GI. Наследуемые `Seed`,
`SampleCount` и `TraceDiffuseBounces` не управляют Realtime; SSAA задаёт выборки
камеры. Общие источники и материалы не изменяются при ограничении их стоимости.

Бюджет вторичных лучей не включает тени: их стоимость ограничена числом света,
его выборок, теневых пересечений и шагов. Рост числа объектов всё ещё увеличивает
стоимость tracer. Эти ограничения не гарантируют заданный FPS на любой сетке.
