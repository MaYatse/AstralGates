# Материалы и карты

`IMaterial.Sample(in TextureContext)` возвращает параметры поверхности один раз
на попадание луча. `DiffuseRenderer` использует результат для всех выборок света.
Первый материал — `DiffuseMaterial`: матовое альбедо, собственное излучение и
необязательная карта нормалей. Модель сохраняет прежний масштаб яркости без
дополнительного деления на π. Зеркальные отражения и BRDF с шероховатостью пока
не реализованы; `ITexture<float>` уже позволяет создавать скалярные карты для
следующих моделей материалов.

```csharp
using System.Numerics;
using HybridSdfEngine.Materials;
using HybridSdfEngine.Textures;
using HybridSdfEngine.SDF.Objects;

var floor = new SdfPlane(Vector3.Zero, Vector3.UnitY)
{
    Material = new DiffuseMaterial(new CheckerTexture<Vector3>(
        new(0.8f), new(0.1f, 0.15f, 0.2f), frequency: 2f, space: TextureSpace.UV))
};

var sphere = new SdfSphere(new(0, 1, 0), 1)
{
    Material = new DiffuseMaterial(new Vector3(0.8f, 0.2f, 0.1f))
};
```

У примитивов `Material` можно менять между кадрами. Если он равен `null`,
рендерер использует прежний `Color`, включая цвет из конструктора. При назначении
материала его альбедо заменяет `Color`; дополнительного умножения на старый цвет нет.
Для объектов без материала UV не вычисляются. Пользовательские SDF продолжают
работать благодаря реализациям по умолчанию в `ISdfObject`.

## Источники параметров

- `ConstantTexture<T>` возвращает постоянное значение. `Value` можно менять между кадрами.
- `CheckerTexture<T>` возвращает одно из двух значений по чётности клетки. `Frequency`
  задаёт число клеток на единицу координат. `TextureSpace` выбирает UV, локальные
  или мировые координаты; по умолчанию используется трёхмерная локальная сетка.
- `ImageTexture` хранит собственную неизменяемую копию RGB-пикселей.
- `ChannelTexture` читает R, G или B у RGB-текстуры и возвращает `float`.
- `TriplanarTexture` смешивает три плоские RGB-проекции с весами по нормали.
  Она удобна для цветовых карт сложных SDF без UV. Это не преобразование normal map.

Пример карты из уже декодированного RGBA8-буфера:

```csharp
byte[] rgba = [
    255, 0, 0, 255,   0, 255, 0, 255,
    0, 0, 255, 255,   255, 255, 255, 255
];
var image = ImageTexture.FromRgba32(2, 2, rgba,
    colorSpace: TextureColorSpace.Srgb,
    addressMode: TextureAddressMode.Repeat,
    filter: TextureFilter.Bilinear);
sphere.Material = new DiffuseMaterial(image);
```

Встроенного декодера PNG/JPEG пока нет: изображение загружается на стороне
приложения, а движок принимает RGB- или RGBA8-буфер. Альфа RGBA игнорируется;
прозрачность и alpha cutout не реализованы. Загрузка и конвертация выполняются
до запуска рендера, выборка текстур не создаёт объектов в куче.

`FromRgba32` по умолчанию считает изображение цветовым sRGB. Конструктор с
`ReadOnlySpan<Vector3>` по умолчанию принимает линейные значения. Для sRGB
преобразование в линейный RGB выполняется при создании текстуры, до фильтрации.
Карты нормалей и скалярных данных следует загружать с `TextureColorSpace.Linear`.
Например, `new ChannelTexture(dataImage, TextureChannel.Green)` извлекает
скалярную карту из G-канала без дополнительного цветового преобразования.

`Nearest` выбирает ближайший тексель, `Bilinear` интерполирует четыре соседних.
Центр текселя `(x, y)` расположен в `((x + 0.5) / width, (y + 0.5) / height)`.
Первая строка изображения соответствует V=0. `Repeat` повторяет изображение,
включая отрицательные UV, `Clamp` растягивает край. Режим применяется к обеим осям.
Mipmap-фильтрации пока нет: билинейная выборка сама по себе не устраняет мерцание
мелких узоров вдали. Существующий SSAA помогает, но повышает стоимость.

## Координаты поверхности

`ISdfObject.GetTextureContext(point)` предоставляет мировую и локальную позиции,
геометрическую нормаль в обоих пространствах, UV и мировой базис TBN.
Локальные координаты примитивов учитывают перемещение и поворот объекта:

- Плоскость: UV в мировых единицах вдоль собственных касательных осей.
- Сфера: долгота/широта; V=0 на северном полюсе, V=1 на южном. Поворот меняет
  текстуру сферы, сохраняя её геометрию. На полюсах используется конечный базис.
- Коробка: UV от 0 до 1 на каждой грани. Выбор грани на рёбрах совпадает с выбором
  геометрической нормали. Между гранями и на сферическом шве возможны швы изображения.

Для произвольного SDF реализация по умолчанию использует мировую позицию как
локальную и создаёт плоские UV по нормали. Это резервная проекция: для корректного
следования текстуры за трансформациями пользовательский объект должен переопределить
`GetTextureContext`. Трипланарный источник также может явно использовать мировое
пространство через `space: TextureSpace.World`.

## Нормали и излучение

```csharp
var material = new DiffuseMaterial(Vector3.One)
{
    // Плоская normal map: +Z в касательном пространстве.
    NormalMap = new ConstantTexture<Vector3>(new(0.5f, 0.5f, 1f)),
    Emission = new ConstantTexture<Vector3>(new(2f, 0.5f, 0.1f))
};
```

`NormalMap` хранит RGB в [0, 1]; они преобразуются в [-1, 1] и затем из
касательного пространства в мировое. Положительная G-компонента направлена вдоль
`Bitangent` (соглашение +Y). Карта с обратным знаком зелёной компоненты требует
её инверсии до передачи движку. Некорректные, нулевые и направленные под поверхность
нормали заменяются геометрической нормалью. Геометрическая нормаль по-прежнему
определяет допустимую сторону освещения и смещение теневого луча.

Альбедо ограничивается диапазоном [0, 1], излучение — снизу нулём. Используйте
конечные значения; излучение может превышать единицу. Оно видно и без источников
света, но само по себе не освещает другие объекты: для этого нужен источник света
или алгоритм переноса непрямого освещения. Height/bump и displacement пока не реализованы.

Все источники параметров читаются параллельно. Менять материалы, текстуры и
трансформации объектов следует между кадрами.
